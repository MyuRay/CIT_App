# アカウントの自動削除

更新: 2026-09-18

マイページのアカウント削除は、お問い合わせによる運営への申請ではなく、本人による自動削除に変更した。現在のパスワードと削除確認が必要。受け付け後はログアウトし、アプリを閉じてもサーバーで削除を続ける。受付と削除完了を同じ状態として表示しない。

## 本人確認と処理

- `deleteMyAccount`: Firebase ID tokenの失効確認とauth_timeが5分以内であることを検証。対象UIDはトークンから決める。本文は `{confirm: true}` だけを許可し、他人のUID指定は拒否する。
- `account_deletion_jobs/{uid}` をトランザクションで作成。重複送信でジョブを増やさない。クライアントからジョブの作成・変更はできない。
- Firestore・StorageルールでジョブのあるUIDを拒否する。削除開始前の有効なID tokenでもデータを再作成できない。
- `processAccountDeletion`: アカウントを無効化・更新トークンを失効し、チェックポイントと10分の排他期限を使ってデータを削除。データ処理が完了した後にAuthユーザーを削除する。
- `retryAccountDeletions`: 15分ごとに未完了ジョブを自動再試行。トリガーも再試行を有効にしている。途中失敗で運営承認待ちにしない。
- 完了済みジョブは古いID tokenによる再作成を防ぐため7日保持した後、自動削除する。ジョブにはメール・パスワード・本文を保存しない。

## 対象

プロフィール配下の全サブコレクション（課題、お気に入り等）、設定、端末通知登録、管理者権限、時間割・出欠、本人の掲示板・レビュー・Cwitter・ちばちゃんねるの投稿とコメント、通知、お問い合わせ、非表示・ブロック設定、Cwitter ID、フォロー・recweet、Excel取り込み学習提出物を対象にする。いいね・アンケート投票・クーポン使用者マップからUIDを除き、該当集計も更新する。

他人の投稿・返信そのものは削除しない。ユーザー専用StorageパスとUID接頭辞の掲示板画像（未投稿画像も含む）を削除する。旧掲示板画像は本人のデータから参照され、他人の残る投稿から参照されていない画像を削除する。管理者が共有コンテンツとして登録した学食メニューなど、個人所有情報のない共通データは削除しない。

通報・BAN等の不正利用対応記録と基盤の監査ログは既存のプライバシーポリシーに従って別管理する。Discord等に既に送られた運営通知の遡及削除はこのアプリデータ削除には含めない。

## 反映と検証

本番ルールは `scripts/prepare-account-deletion-rules.cjs` でLIVEルールを取得し、削除中のアクセス拒否のみを追加した設定を `.firebase/deletion-deploy/` に作る。ローカルの他機能の未反映ルールを混ぜずに反映する。元の本番ルールは同フォルダの `.before` に保存する。ローカルルールにも同じガードを追加する。

```powershell
node scripts/prepare-account-deletion-rules.cjs
npx firebase deploy --project cit-app-2de1c --config .firebase/deletion-deploy/firebase.json --only "firestore:rules,storage"
npx firebase deploy --project cit-app-2de1c --only "functions:deleteMyAccount,functions:processAccountDeletion,functions:retryAccountDeletions" --force
node scripts/test-account-deletion-production.cjs --project cit-app-2de1c --run
```

本番テストは専用のランダムUIDのAuthアカウント、非公開サブコレクション、専用Storageファイルだけを作る。プロフィール親ドキュメント・投稿・お問い合わせは作らず、外部通知を発生させない。未認証・別UID指定の拒否、古いトークンでの書き戻し拒否、ワーカーによる自動削除の完了を確認する。

Node単体テスト9件、Firestoreエミュレーターによる権限・途中失敗からの再開テスト2件、削除画面5件が成功。画面はライト・ダーク、320px、文字200%、下部システム余白48pxを確認した。

2026-09-18に上記の本番ルールと3関数を反映。既存の権限検証を含むFirestoreテスト全30件が成功した。本番の専用テストではHTTP 202で受付後、古いID tokenの書き込みが403になり、ワーカーがAuthアカウント・課題と端末登録の子ドキュメント・Storageファイルを削除してジョブがcompleteになることを確認した。

初回検証で大量の既存データを確認する際の進捗保存コストを確認し、100件単位で保存するよう改善した。削除・集計更新自体は冪等なので、ページ途中の障害でも再処理できる。段階途中で実行時間上限に達したジョブの再開は定期再試行が担当する。

改善前の最初のテストは7分で途中保存し、テスト側の450秒待機はタイムアウトした。その後、Cloud Schedulerの再試行ジョブを即時実行して再開を確認した。改善後の別テストは通常トリガーだけで完了した。最終確認で両方のジョブがcomplete、両方のAuth・非公開テスト文書・Storageファイルが存在しないことを確認済み。
