# 学年別の広告配信・広告分析

- 管理センター → 配信・スポンサー → 広告管理の作成・編集で「対象学年」を複数選択できます。未選択は全員、既存の広告も従来どおり全員が対象です。
- 学年は認証済みメールの学生番号先頭2桁を入学年度として推定します。旧学部ドメイン `s.chibakoudai.jp` と `chibatech.ac.jp` の学生番号形式に対応し、日本時間の4月1日に更新します。大学院用 `p.chibakoudai.jp`、職員・テストアドレス、形式不明は「判定不可」です。留年・編入などの実学年を保証するものではありません。
- 広告管理の右上のグラフボタンから広告分析を開けます。広告・掲載場所・学年で絞り込み、場所と一覧位置ごとに表示数・クリック数・クリック率を確認できます。期間は当日を含む日本時間の7日／30日／90日です。
- 固定バナーの位置は「固定枠」、繰り返しバナーは一覧内の行番号です。ちばちゃんねるのスレッド一覧ではホットスレッドから通常スレッドにかけて行番号を通算します（見出しを除く）。
- 表示はバナーの50%以上が画面内に入った時点で、同じバナーの表示インスタンスにつき1回記録します。クリックは操作回数です。件数はユニークユーザー数ではなくクライアントからの計測値です。
- イベントは `ad_events` に保存します。保存するのは広告ID・場所・位置・推定学年・イベント種別・サーバー時刻だけで、メールアドレスやUIDは保存しません。「利用状況データの送信」がオフの場合は記録しません。
- 2026-11-17修正：学年判定はアプリ本体と同じ認証ストリームを監視し、起動直後もFirebaseが復元した認証済みセッションを使用します。計測時には現在の認証済みメールから学年を再計算するため、ウィジェットから渡された一時的な `unknown` や以前のアカウントの学年は保存しません。Firebase Analyticsも同じ認証情報から判定します。氏名・メール・UIDを計測データへ追加して復元する方式ではありません。
- 集計は期間内の最新5,000イベントまでです。上限を超える場合は画面に表示されます。絞り込みも取得したイベント内に適用されます。過去のイベントの学年は計測時の値を保持します。更新前のクリック履歴の学年・位置は復元できません。
- 管理センター上部の「ボトムの管理タブを表示」で端末ごとにオン・オフできます。管理タブを隠しても、マイページから管理者機能を開けます。

## Firebaseへの反映

広告分析を初めて導入する場合は `firestore.rules` の広告用ルールの反映が必要です。現在のリポジトリには他機能の未反映差分もあるため、本番ルールとの比較なしで全文を置き換えないでください。手動貼り付け用の `docs/firebase-contact-chat/firestore.rules` にも広告の変更を反映しています。今回の学年判定修正ではルールや保存項目を変更していません。

追加する `ad_events` は認証済みCITユーザーの検証済みイベント作成と、管理者の読み取りだけを許可します。更新・削除、余分なフィールド、対象外学年・場所・期間のイベントは拒否します。`in_app_ads.targetGrades` は管理者だけが編集できます。

Functionsの変更や追加の複合インデックスは不要です。計測は更新版アプリとルールの反映後から始まります。

flutter test test/services/ads/ad_targeting_test.dart test/widgets/ad_targeting_test.dart test/widgets/ad_management_test.dart test/services/ads/ad_management_query_test.dart
