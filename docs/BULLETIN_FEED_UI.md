# 掲示板一覧のUI

2026-09-16更新。投稿作成・詳細・カテゴリ・ピン留め・スポンサー表示・複数画像・コメント件数・ページ追加読み込みを維持し、一覧の構成を変更した。

- 投稿はスマホ・広い画面ともに2列表示。本文幅は最大1120px、列間は12px、行間は14px、カード内の余白は左右12px・上下14px。カテゴリとタイトルの間は10px、投稿者の前は12pxとし、情報のまとまりを分ける。幅は統一し、高さは内容に合わせる。画像やスポンサー帯がないカードに、その分の高さを確保しない。奇数件の最後も片列の幅を保つ。
- タイトルと本文概要は各1行まで。表示幅を超える部分を「…」で省略し、改行・連続する空白は一覧表示でのみ1つの空白にまとめる。短いタイトルや空の概要のための空行は作らず、全文・元の改行は詳細画面に残す。高さの上限固定や余白を伸ばすSpacerは使わない。文字拡大時も行の高さは設定に従う。
- 日付と閲覧・コメント件数は同じ領域に詰め、幅が足りない場合は折り返す。カードは上端を揃えた2列の行を `SliverList` で必要な分だけ構築し、行の高さはその行に含まれるカードで決める。
- スポンサー名と「広告」はコンパクトな金色の帯で表示する。
- 画像付きの投稿は16:9の選択サムネイルを表示し、複数画像の枚数を重ねる。画像のない投稿にはダミー画像領域を出さない。
- ピン留め投稿はカテゴリの左隣にピンのアイコンだけを表示する。読み上げでは「ピン留め」と伝える。続いてタイトル、本文の概要、投稿者、日付・閲覧数・コメント数を表示。本文全体は詳細画面で読める。
- 「ピン留めを優先」と一覧末尾の「ここまでが現在の投稿です」は表示しない。ピン留めの優先順と追加読み込み・再試行の操作は維持する。
- ピン留めは通常の新着30件とは別に全件取得するため、古い投稿も初回から先頭に表示する。新着取得側との重複は投稿IDで除去する。同じピン留め状態なら作成日時の降順、同日時なら投稿IDの降順で固定する。
- ピン留めと読み込み済みの新着範囲はFirestoreの更新を購読し、ピン留めの追加・解除、非公開化、削除を反映する。期限切れはタイマーでも除外し、承認待ち・ブロックした投稿者・選択外カテゴリを優先表示で復活させない。
- スポンサーは既存の金色パレットと「広告」表示を使用。カテゴリの文字色は背景とのコントラストを補正する。
- カテゴリは横スクロールで選択。「すべて」を明示し、切り替え時は一覧の先頭へ戻す。投稿ボタンにはラベルを付け、小画面・大きな文字設定ではツールチップ付きのアイコンにする。
- 投稿が0件でも引っ張って更新できる。追加ページが残っている場合は「以前の投稿を読み込む」を表示するため、現在のページに該当カテゴリがない場合も続きを確認できる。
- 読み込み失敗時には再試行ボタンを表示し、内部エラーの文字列を画面に表示しない。追加読み込みが失敗した場合は既存の投稿を保持し、自動連続リトライを止める。
- 追加読み込みは新着の購読範囲を30件ずつ広げる。範囲の再購読では読み込み済み分も取得対象になるが、動くカーソル境界で投稿が抜けることを防ぐ。全件読み込み後の同期失敗にも再試行を表示する。更新・ログアウト・破棄後に以前の購読結果で上書きしない。

一覧は `lib/screens/bulletin/bulletin_screen.dart`、カードは `lib/widgets/bulletin/bulletin_feed_card.dart`。データの公開範囲、ブロックによる絞り込み、並び順、保存形式は従来のプロバイダーを使用する。

取得と先頭への並べ替えは `lib/services/bulletin/bulletin_feed_service.dart`、購読の切り替えは `lib/core/providers/bulletin_provider.dart`。新着クエリは従来と同じ承認状態＋作成日時、ピン留めクエリは `isPinned == true` の単一フィールド条件で、新しい複合インデックスは追加していない。オフライン時はFirestoreのキャッシュに含まれる投稿を表示し、再接続時に更新される。

購読の仕様: [Firestoreのリアルタイム更新](https://firebase.google.com/docs/firestore/query-data/listen)。ピン留めの取得範囲・表示順・購読の構成はこのアプリの実装上の方針。

`test/widgets/bulletin_feed_test.dart` でカテゴリ切り替え、空状態での更新、初回・追加読み込みの失敗、画像有無、コメントの読み上げ、両テーマ、320px・文字200%・システムナビゲーション用48pxの余白、タブレットを確認する。`THEME_PREVIEW_DIR` を指定するとテスト用投稿の画面プレビューを出力する。本番にテスト投稿は作成しない。
