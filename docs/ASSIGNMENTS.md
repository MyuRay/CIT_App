# 課題管理

時間割の学期ボタンのすぐ右（間隔8px）の「課題」で、時間割を横に回転させて課題一覧に切り替える。「時間割」で戻り、Androidの戻る操作でも時間割へ戻る。端末のアニメーション抑制設定時は即時に切り替える。講義通知・出欠管理・編集・共有は個別ボタンで操作する。画面幅384px未満または文字拡大時は操作ボタンを2段目に配置し、三点メニューにまとめない。

## 登録・管理

時間割タブを表示中に下部の「時間割」をもう一度押すと、課題管理へフリップする。課題管理を表示中に押すと時間割に戻る。他のタブから時間割を開く操作ではフリップしない。

- 課題一覧の「課題を登録」、時間割／ホームの講義詳細の「この講義の課題を登録」、ホームの課題カードから登録する。
- 課題名は任意・120文字まで。空欄や空白のみの場合は「課題」で保存する。締切日は必須、締切時刻は任意。時刻未指定の場合は指定日の終わりが締切。メモは任意・4000文字まで。
- 登録時の講義候補は、時間割タブで現在選択している時間割に限定する。講義詳細からはその講義を自動選択し、一般の登録では講義を選ぶか、講義に紐づけず保存できる。連続講義は候補を重複させない。講義名の後ろに学期の括弧書きは表示しない。
- 全学期の未完了課題を締切順に表示する。同じ締切はIDで順序を固定。日付に加えて「今日」「明日」「期限超過」を表示する。
- チェックで完了／未完了を切り替える。本文タップで編集、操作メニューで編集・削除。削除には確認がある。完了した課題は「完了」から確認・復帰できる。
- 登録・編集の失敗時は入力内容を維持する。保存中の重複送信を抑制し、同じ登録IDで再試行する。編集中に別端末から削除された課題は復活させない。編集保存は別端末の完了状態を上書きしない。
- 講義・時間割を削除しても課題と登録時の講義名は残る。別の時間割に切り替えてから既存の課題を編集しても、登録済みの紐づけは保持する。紐づけの変更先は現在選択中の時間割の講義とし、解除もできる。

## ホーム

- 初期配置は「今日の時間割」の直下。既存の保存済みレイアウトにもその位置に追加する。
- 見出しは他のホームカードと同じアイコン・文字サイズ・余白に揃え、未完了件数は見出し横のバッジで表示する。
- 未完了の課題を締切順に最大3件表示。「課題管理を開く」から全件を見る。
- 未完了が0件になればカードを自動非表示にする。表示設定で明示的に非表示にした場合は新規登録後もその設定を優先する。
- ハンバーガーメニュー → ホームカードを編集 → 課題を表示 → 保存、で空でも表示する。未登録なら「現在課題は登録されていません」、全件完了なら「課題はすべて完了しました」と表示する。
- 手動の表示設定は既存のホームレイアウト設定に保存する。「デフォルトに戻す」で自動表示に戻る。
- 通信エラーを0件と扱わず、カード内にエラーと再読み込みを表示する。

## チュートリアル

2026-09-18、使い方ガイドの時間割の次に課題管理ページを追加（全6ページ）。学期ボタン横の「課題」→登録→締切確認→完了→未完了への復帰を、実際にタップできる見本で案内する。見本は端末内の画面状態だけで動作し、実際の課題を作成・変更しない。「課題管理を開く」は時間割タブの課題一覧を直接開く。

ガイドの既読バージョンは2.1.0。旧ガイドを見たアカウントにも更新版を一度表示する。マイページからの再表示と、最後のメインキャンパス設定・保存は維持する。

関連テスト20件成功。ライト／ダーク、幅320px・文字200%、横向き640×360px・文字160%、システムナビ領域48pxで全ページと課題操作を確認。プレビューは `docs/qa/tutorial/assignments/`。静的解析はエラー・警告なし（既存ホーム見本のonReorder非推奨infoは残る）。

## 保存・運用

`users/{uid}/assignments/{assignmentId}` に保存。アプリ内の時間割・ホームは同じストリームを購読する。アカウント変更時は前アカウントのデータを引き継がず、古い編集画面からの保存を拒否する。

フィールドは `title`, `notes`, `dueAt`, `hasDueTime`, `course`, `isCompleted`, `createdAt`, `updatedAt`。`course` はnullまたは `scheduleId`, `classId`, `subjectName`, `semester`。複合インデックスは不要。

Firestoreルールは大学メール認証済みの本人に限って読み書きを許可する。管理者や他ユーザーの閲覧は許可しない。追加ルールを反映してから対応アプリを配布する。課題内容をAnalyticsや通知へ送信する処理はない。

アカウントの自動削除では `users/{uid}/assignments` も再帰的に削除する。親の `users/{uid}` 文書を削除するだけではサブコレクションは消えない。実装・本番反映は `docs/ACCOUNT_DELETION.md` を参照。
