# CIT App リファクタリング提案

更新日: 2026-09-07

## 画面文言の方針（2026-09-16）

全画面でキャッチコピー、利用を促すだけの呼びかけ、挨拶や長い前置きを入れない。見出しは機能名、空の状態は現在の状態、案内は操作手順を直接記載する。入力条件、エラー、確認事項、規約など判断に必要な説明は残す。文言を削除した際は、専用の余白や空のカードも取り除く。共有テキストにアプリの宣伝文を自動で付け足さない。

## 今回対応した内容

- `main_screen.dart` に重複して残っていた旧通知・プロフィール・問い合わせ画面を削除した。
- 掲示板画面を `screens/bulletin/bulletin_screen.dart` に移し、機能単位の責務へ戻した。
- メインナビゲーションを独立したウィジェットにし、タブ番号と表示定義を一元化した。
- タブを遅延生成し、一度開いた画面のスクロール位置や入力状態を維持するようにした。
- 新着表示を小さなドットへ統一し、読み上げでは「新着があります」と伝わるようにした。
- 掲示板の一覧を画面幅に応じたレスポンシブグリッドへ変更した。
- Webでモバイル専用のファイルキャッシュとホームウィジェット処理を実行しないようにした。
- App Check のダミーreCAPTCHAキーを廃止し、Webではビルド設定がある場合だけ有効化するようにした。
- ホームウィジェットの購読を破棄時に解除し、実体のない定期ログを実フレーム計測へ置き換えた。
- 古いログイン画面テストを、独立して再現可能なナビゲーションテストへ置き換えた。
- Dartの安全な自動修正を適用し、非推奨APIや不要importなどを更新した。

## 次に直すべき場所

### P0: ログの個人情報を除去する

認証、管理者、コメント周辺でメールアドレス、UID、トークン関連情報を直接ログへ出している箇所がある。共通ロガーへ集約し、リリースビルドでは個人識別情報を出さないことを最優先にする。

推奨実装:

- `SecureLogger` だけを利用するルールにする。
- メール、UID、URLクエリ、Firebase Storageトークンを自動マスクする。
- `avoid_print` を段階的にエラー扱いへ引き上げる。
- デバッグログと運用監視イベントを分離する。

### P0: Web版App Checkの本番設定を確定する

Web版は `FIREBASE_RECAPTCHA_SITE_KEY` が設定された場合だけApp Checkを有効化する。デプロイ時に正しいキーを渡し、Firebase側でトークン取得と強制適用を確認する。

推奨ビルド例:

```text
flutter build web --dart-define=FIREBASE_RECAPTCHA_SITE_KEY=<site-key>
```

### P1: 巨大画面を機能単位へ分割する

特に次のファイルは変更の衝突と回帰リスクが高い。

- `home_screen.dart`: 約5,600行
- `floor_map_with_pin_viewer.dart`: 約4,600行
- `bus_management_screen.dart`: 約3,100行
- `schedule_screen.dart`: 約2,500行
- `bulletin_post_form_screen.dart`: 約2,100行
- `bulletin_post_detail_screen.dart`: 約2,000行

まずホーム画面を「天気」「次の授業」「電車」「バス」「学食」「キャンパスマップ」のセクションへ分割する。HTTP取得やFirestore操作は画面から外し、サービスまたはRiverpodのNotifierへ移す。1ファイル300〜500行程度を目安にするが、行数より責務の境界を優先する。

### P1: 非同期処理後の画面操作を安全にする

静的解析では、非同期処理後に破棄済みの画面へダイアログやSnackBarを出す可能性がある箇所が残っている。`await` 後に `context.mounted` を確認し、画面遷移・通知処理を共通ヘルパーへ寄せる。

### P1: 未使用コードを削除する

静的解析に未使用メソッド・フィールドが残っている。コメントアウトされた旧実装を保持するのではなく、履歴はGitへ任せて削除する。特にホーム、掲示板詳細、バス管理から進める。

### P2: データ層の境界を揃える

画面からFirebase、HTTP、端末APIを直接呼ぶ実装が混在している。段階的に以下へ揃える。

```text
feature/
  data/          Firebase・HTTP・端末API
  domain/        モデル・判定ロジック
  presentation/  Provider・画面・Widget
```

全面移行は避け、変更頻度の高いホームと時間割から機能単位で移す。

## UI / UX 改善案

1. ホーム最上部を「今やること」にする。次の授業、教室、出発目安、遅延情報を1枚にまとめ、天気やお知らせはその後に配置する。
2. カードの優先度を「必須・よく使う・その他」の3段階にする。ユーザーが並び替えなくても初期状態で重要情報が上に来るようにする。
3. 読み込み・空・失敗状態を共通化する。再試行ボタン、最終更新時刻、オフライン表示を全機能で同じ位置と文言にする。
4. タブレット・Webでは横幅を制限するか複数列へ切り替え、カードが横に伸びすぎないようにする。
5. タップ領域を最低48dpに統一し、色だけで状態を表さない。新着、運休、締切などにはアイコンと短い文言を併用する。
6. 投稿や問い合わせの入力中離脱確認を共通化し、送信中・成功・再送の状態を一貫させる。

## おすすめ機能

### 1. 今日の行動タイムライン

時間割、教室、電車、学バスを時系列でまとめる。単なる情報一覧ではなく、「あと何分で出る」「次は何号館」のように次の行動を示す。CIT Appの既存機能を最も活かせる改善。

### 2. キャンパス横断検索

教室、掲示板、学食、サークル、各種リンクを1つの検索欄から探せるようにする。ホーム上部から利用でき、結果は種類ごとに表示する。

### 3. お気に入りとオフライン利用

よく使う教室、路線、掲示板カテゴリ、学食メニューを保存し、直近データは通信できない場面でも表示する。更新日時を必ず添える。

### 4. 通知の要約と静かな時間

授業、掲示板、交流の通知をカテゴリ別に設定し、夜間はまとめて配信できるようにする。通知を増やすより、ユーザーが制御できることを優先する。

## 品質基準

- `flutter test` を常時成功させる。
- 静的解析はまずエラー0を維持し、警告を機能単位で0へ減らす。
- 新しい画面には最低1つのWidgetテスト、判定ロジックにはUnitテストを追加する。
- Android、iOS、Webで利用できないAPIは、サービス層で明示的に分岐する。
- 新規のFirebase読み書きには成功・権限不足・オフラインの3ケースを用意する。
