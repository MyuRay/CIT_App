# Excel時間割の抽出精度改善

確認日：2026-09-16。

`excel_import_training/` に追加された424件のExcelをローカルで分析し、講義名・担当教員・教室を抽出する処理へ書式パターンを反映した。学習結果は `lib/services/schedule/excel_lecture_fields.dart` の抽出ルールと `test/fixtures/excel_import_cases.json` の回帰検証例として保持する。

## 判定方法

大学の出力では、1つの講義セル内でも文字列が複数のExcel行へ分割される。タイトルの末尾に教員名らしい短い文字列が現れることもあるため、場所・キャンパス・単位などの境界を先に探し、その直前の教員欄から講義名と教室欄を分ける。

- 講義名の途中で分かれた漢字・かな・数字を連結する。学科・クラス・奇数／偶数などの区別を保持する。`※` 以降の別カリキュラムの名称はタイトルに混ぜない。従来と同じく末尾の「コース」「○年」の管理用表記は必要に応じて除く。
- 教員名は「﨑」などの互換漢字、ひらがな、かなと漢字の混在、英字、複数行に分かれたイニシャル付き氏名、外部講師の組織名・役職に対応。「学番」「奇数」「偶数」などの受講条件を教員名にしない。
- 教室は複数行を連結してからキャンパス表記を分離する。工作室、製図室、PC演習室、教室番号の後ろの括弧書き、フレキシブルワークスペースなどを保持する。全角英数字は半角に統一する。
- 教室未記載のファイルは空欄を保つ。教員が未記載・非公開・判別不能の場合も空欄とし、取り込み確認画面へ警告を渡す。他の学生の履修例から教室や教員を補完しない。

前期／後期の選択、曜日・時限、連続講義の統合、編集後の保存、任意の資料提供は既存の処理を維持する。

## 資料と検証

資料424ファイルは計1,423シート。時間割部分は延べ17,684コマ、行の内容と位置を重複排除すると1,696種類の講義セルがあった。実際の取り込み処理でも424ファイルすべてが読み込め、706学期分・7,989講義・17,684コマを抽出した。複数回提供された履修内容も含むため、これらはユニークな授業数・利用者数ではない。

元の行を人が読み、期待値を指定した58例を回帰テストにした。教員名は架空名へ置換し、文字種や分割位置を保持している。ファイル名・利用者ID・学生の氏名・学籍番号・時間割全体をテスト用データに含めていない。

| 期待値との厳密一致 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 講義名 | 13 / 58 | 58 / 58 |
| 担当教員 | 43 / 58 | 58 / 58 |
| 教室名 | 45 / 58 | 58 / 58 |
| 3項目すべて | 10 / 58 | 58 / 58 |

この58例は分割や誤認が起きやすい既知の例を選んだもので、全424ファイルや未知の書式の正解率を示すものではない。全件検証は読み込み・抽出範囲・異常終了の確認であり、全件に人が正解ラベルを付けたわけではない。

全体テストは462件成功、任意の単一Excelサンプルを要求する旧テスト1件は未指定でスキップ。今回の対象5ファイルの解析はエラー・警告・infoなし。Androidのdebug APKビルドも成功（Gradle 24.7秒）。実機でのファイル選択から取り込み確定までの操作は未確認。

## 再検証

通常の回帰検証は資料がなくても実行できる。

```powershell
flutter test test/services/schedule/excel_lecture_fields_test.dart test/services/schedule/excel_schedule_import_test.dart test/widgets/excel_import_review_dialog_test.dart
```

追加資料を含む全件監査は、ローカル資料のフォルダを指定して実行する。

```powershell
$env:CIT_IMPORT_TRAINING = (Resolve-Path ./excel_import_training).Path
flutter test test/services/schedule/excel_import_training_corpus_test.dart
Remove-Item Env:CIT_IMPORT_TRAINING
```

集計は `build/excel-training/corpus-audit.json` に出力する。監査は読み取りのみで、Firebaseへ保存しない。`excel_import_training/` はGitの対象外で、アプリのassetsにも含めない。新しい書式が見つかった場合は、原本を保持し、個人情報を除いた小さな例と人が確認した期待値を追加してから抽出処理を修正する。
