# CIT App 2.3.0 公開準備

確認日：2026-09-16。アプリは **2.3.0+81**。審査提出・公開は未実施。

## この版で追加した公開対策

- Androidのcompile / target SDKを36に固定。署名設定がない場合に開発用の鍵へ切り替える処理を廃止。
- スポンサー広告の表示・タップ計測を保ち、広告ID・AdServicesの権限とAnalyticsの広告ID取得・広告パーソナライズを無効化。
- 写真・動画全体へのアクセス権限を要求しない既存設定を維持。QR・撮影のためのカメラは任意の端末機能として宣言。
- アカウント削除画面を修正。以前はAuthアカウントとusersの親文書だけを削除し、関連投稿・画像等が残る可能性があった。現在は関連データも対象とする削除申請を既存のcontact_formsへ保存し、受付番号を表示する。保存前・失敗時に受付済みとは表示しない。
- 削除は運営が行う方式。管理センター → 問い合わせ → 未対応 → アカウント関連で扱う。申請者の確認、対応予定の案内、関連データの削除、メールでの完了連絡が必要。**チケットを解決済みにするだけでは削除は実行されない。** アカウント停止だけで完了にしない。
- アプリ外の削除申請用に `web/account-deletion.html` を用意。**まだ公開していないため、このファイルのURLをPlay Consoleへ登録してはいけない。** 管理するWebサイトに掲載し、ログイン不要で開けることを確認してから使用する。
- 編集モードで講義を長押ししてドラッグ＆ドロップで移動。連続講義はまとめて移動し、重複した移動先は赤枠と「重複」を表示して元の位置に戻す。画面端で自動スクロール。衝突と同時編集を検出し、一括保存で移動元の消失を防ぐ。ホームの表示、講義通知、ホーム画面ウィジェットも更新する。スクリーンリーダーには曜日・時限を選ぶ移動操作も提供する。

## 提出前に解消する項目

1. **既存のアップロード鍵**：`android/key.properties` は未設定。`android/key.properties.example` を参考に既存の鍵を指定する。新しい鍵で既存アプリを更新できるとは限らないため、無断で鍵を作り直さない。Play Consoleの「アプリの完全性」にあるアップロード証明書と照合する。
2. **ビルド番号**：81はローカルの80から増やした値。Play Consoleの全トラック・下書きの最大値は未確認。使用済みなら、それを上回る番号に変更して再ビルドする。
3. **Firebase本番との整合**：`docs/handoff/releases.md` の認証・通知修正、スポンサー用ルール等の反映状況を確認する。ローカルのルール・Functions変更が本番に入ったとは扱わない。最新クライアントだけを先に公開しない。
4. **アプリへのアクセス権**：学内メールによる制限があるため、既にメール認証を済ませた審査用アカウントと英語の操作手順をPlay Consoleに登録する。追加認証・学内ネットワークなしで必要な機能を確認できることを内部テスト版で検証する。認証・App Checkを無効にする回避策は使わない。
5. **データ セーフティと広告**：`play-console-copy-2.3.0.md` を元に実際の送信先・運営方法と照合して更新する。広告IDを使わなくてもスポンサー掲載は広告あり。申告の保存は未実施。
6. **公開プライバシーポリシー**：公開ページの外部サービス説明は旧内容だった。アプリ内の最新版と整合させる。公開ストアのリンク先はNotionで、本作業では正常表示を確認できなかった。登録するURLが公開・ログイン不要で開くことを確認する。
7. **削除の運用**：受付窓口を監視する担当者を決め、申請→関連文書・サブコレクション・画像等の削除→完了連絡までテスト用アカウントで確認する。連携先に送信した個人データ、Analyticsの過去データの扱いも確認する。現時点で全データ削除の実運用は未検証。
8. **最終テスト**：Play内部テストで起動、ログイン、画像選択、長押し移動、通知、出欠、通報・ブロック、削除申請の管理者側受付、ライト・ダーク、3ボタンナビを確認。事前公開レポートでクラッシュ・ANR・表示不具合を確認する。16 KBは静的検証に加えて対応端末／エミュレータで確認する。

Play Consoleへのアクセスは案内ページへ戻る状態のため、管理画面の登録値・ポリシーステータスは未確認。

## ビルドと検査

署名設定後の提出用ビルド：

```powershell
C:\flutter\bin\flutter.bat build appbundle --release
./scripts/verify_android_bundle.ps1 -BundlePath build/app/outputs/bundle/release/app-release.aab -BundletoolPath build/bundletool-all-1.18.3.jar
```

署名鍵がない環境でのローカル検査専用：

```powershell
C:\flutter\bin\flutter.bat build appbundle --release --android-project-arg=citUnsignedRelease=true
./scripts/verify_android_bundle.ps1 -BundlePath build/app/outputs/bundle/release/app-release.aab -BundletoolPath build/bundletool-all-1.18.3.jar -AllowUnsigned
```

未署名ファイルはPlayへ提出できない。検査スクリプトは実際のAABのパッケージ・版・SDK・権限・広告ID設定・デバッグ指定・16 KB設定・64bit ELFのLOADセグメント・署名を検証する。署名があってもPlayに登録済みの証明書との照合は別途必要。

bundletool 1.18.3はGoogle公式GitHub配布を取得し、GitHubが公表するSHA-256と一致を確認した。検査ログ・テスト結果は最終確認後に末尾へ記録する。
