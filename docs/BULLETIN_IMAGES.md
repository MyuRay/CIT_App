# 掲示板の複数画像・サムネイル

## 利用方法

- 投稿・編集画面の「画像を追加」から写真をまとめて選択、またはカメラで撮影。最大10枚、1枚10MBまで。選択画像は最大2048px・品質85で取り込む。
- 横並びの画像を長押しすると掲載順を変更できる。タップした画像を一覧のサムネイルに設定し、×で投稿から取り除く。
- 「表示範囲を調整」で16:9の一覧と同じ範囲を確認。ドラッグで位置、ピンチまたはスライダーで倍率（1〜4倍）を調整できる。「この範囲にする」で反映。「キャンセル」は変更を破棄する。
- 画像を切り替えるとサムネイルの位置・倍率は中央・1倍に戻る。並べ替えだけでは選択画像と調整値を維持する。
- 投稿詳細と管理者プレビューでは全画像を掲載順に表示。スワイプ／左右ボタンで切り替え、タップで全画面表示できる。
- 一覧カードは選択サムネイルと画像枚数を表示。画像そのものは切り抜かず、詳細から元画像を確認できる。

## 保存形式・互換性

`bulletin_posts` の `imageUrls` は掲載順のURL配列。従来の `imageUrl` は選択サムネイルのURLとして維持する。`thumbAlignX` / `thumbAlignY` は -1〜1、`thumbScale` は1〜4（初期値1）。

既存の `imageUrl` だけの投稿も1枚のギャラリーとして表示・編集できる。移行バッチは不要。画像一覧から外れたサムネイル指定や不正な調整値は読み込み時に補正する。旧バージョンのアプリは選択サムネイル1枚を表示し、新しい拡大率には対応しない。

画像は従来と同じ `bulletin_images/` に保存する。投稿データの保存が成功した後に、編集で除いた画像を削除する。保存失敗時は既存画像を維持し、同じ画面での再試行はアップロード済み画像を再利用する。新規投稿のIDも再試行時に固定する。画像選択中・保存中の二重送信を防ぐ。

通信エラー後に画面を閉じた場合、保存成否を確定できない画像は自動削除せず残す。参照中の画像を消さないための扱いで、未参照画像の定期削除は別途未実装。管理者の一括削除は従来どおり投稿データの削除のみ。

ローカル `firestore.rules` の投稿者向け更新許可フィールドに `imageUrls` と `thumbScale` を追加。2026-09-16に読み取り確認した本番ルールは、今回の追加項目の保存を妨げるフィールド制限がなく、この機能のための本番デプロイは不要だった。本番ルール自体は変更していない。

## 実装と検証

- `bulletin_image_draft.dart`: 画像の追加・削除・並べ替え、サムネイル選択。
- `bulletin_image_save_session.dart`: アップロード、保存後の不要画像削除、再試行。
- `bulletin_image_picker.dart` / `bulletin_thumbnail_editor.dart`: 投稿・編集共通UI。
- `bulletin_thumbnail.dart`: 一覧と編集画面共通の表示・位置計算。
- `bulletin_image_gallery.dart`: 詳細・管理者プレビュー共通UI。
- `test/services/bulletin/bulletin_images_test.dart`: 旧データ互換、保存、再試行、削除タイミング、座標計算。
- `test/widgets/bulletin_images_test.dart`: 複数選択、並べ替え、ドラッグ、ピンチ、キャンセル、両テーマ・320px・文字倍率200%。
- `test/widgets/sponsor_management_test.dart`: 管理者の複数画像プレビューと既存掲示板表示。
- `test/firestore/access.rules.test.cjs`: ローカルルールで投稿者・管理者の画像編集を許可し、他の読者による編集を拒否。
