# 匿名ID対応表のアクセス制御

2026-11-16、ローカル修正。本番未反映。

`chiba_channel_threads/{threadId}/anonymous_ids/{userId}` は投稿者UIDと匿名IDの対応表である。従来は学内認証済み利用者が全件読み取れたため、次に変更した。

- 本人は自分の文書だけ取得できる。未作成時の確認と、存在するスレッドへの自分の匿名ID作成は維持する。
- 管理者は運営上の確認のため取得・一覧・削除ができる。
- 他人の文書取得、一般利用者の一覧取得、他人名義の作成、ID変更、削除済みスレッドへの追加は拒否する。スレッド作成者にも他人の対応表を開示しない。

スレッド削除時にアプリが対応表を列挙する処理を除き、`cleanupChibaPrivateMappings` が削除後にサーバーで後片付けする。100件ずつ処理し、途中失敗は再試行する。各トランザクションで親スレッドの不存在を確認するため、遅れて届いた削除イベントで再作成済みスレッドの対応表を削除しない。

## 反映時の注意

本体と問い合わせ用のルール双方に同じ修正を入れた。新しい削除関数・アプリ・読み取り制限を揃えて反映する必要がある。旧アプリは削除前に対応表を一覧取得するため、制限反映後はスレッド削除が失敗する。最低対応バージョンの案内・更新制御を先に準備する。既に消えたスレッドの対応表について、削除イベントを遡って実行するものではない。

**これは匿名性の問題全体の解消ではない。** 公開範囲の投稿・コメントに残る `authorId`・`authorEmail`、ユーザープロフィール、画像URL、返信通知、通報時の本人情報の取り扱いは、引き続き分離・移行が必要。既に取得された情報の回収も保証できない。公開ポリシーの配信条件は `legal/README.md` を参照。

検証ファイル：`test/firestore/chiba_private.rules.test.cjs`（両ルールを対象）、`functions/test/chiba_private_cleanup.test.js`（大量件数・再試行・親の再作成）。

検証結果：本体ルール4件・問い合わせ用ルール4件・削除処理の単体5件が成功。変更したDartサービスの静的解析も指摘なし。エミュレーターはメタデータ探索・OpenTelemetryを無効にし、外向きHTTP/HTTPS/SOCKS通信を接続しないループバック先に設定して検証した。実ユーザーのデータは取得・変更していない。
