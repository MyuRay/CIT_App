# スポンサー枠と掲示板管理

確認日: 2026-09-16

## 管理者の操作

### 掲示板

管理者メニュー → 掲示板管理 → 対象投稿の「掲載設定」を開く。

- 「金色のスポンサー枠」を有効にし、企業・店舗名を入力して保存する。
- スポンサー名は1〜80文字。金色の枠と「広告」ラベルが一覧・投稿詳細に表示される。
- 掲載の有効／無効、ピン留め、コメント許可、掲載期限を同じ画面で設定できる。
- 期限は選択日の終わりまで。保存画面には実際の掲載終了日時を表示する。
- スポンサー枠にしても承認状態は変わらない。公開には、承認済み・掲載有効・期限内の条件が必要。
- 金色の枠とピン留めは別設定。スポンサー枠だけでは掲載順を変更しない。
- 本文を編集すると従来どおり再審査になる。スポンサー設定・閲覧数・クーポン使用記録は保持する。

管理画面上部の件数から「公開中」「承認待ち」「スポンサー」で絞り込める。検索はタイトル・本文・投稿者・スポンサー名が対象。カテゴリ、作成日時・閲覧数・掲載期限での並べ替えも利用できる。

複数選択では最大400件の公開設定、ピン留め、期限延長、削除を操作できる。検索やフィルター変更で選択を解除し、非表示になった投稿への誤操作を防ぐ。期限切れの投稿を7日延長すると、現在日時から7日後に設定する。削除には確認画面があり、実行後は元に戻せない。

CSVコピーは、現在の検索・絞り込み・並び順を反映した投稿だけが対象。スポンサー名・掲載期限も含める。

### アプリ内広告

管理者メニュー → 広告管理 → 作成／編集で「金色のスポンサー枠」を設定する。

広告一覧は「掲載中・予約中・停止中・終了」の件数で絞り込める。掲載状態は配信設定と開始・終了日時から判定し、画面表示中は1分ごととアプリ復帰時に更新する。「有効」でも開始前は予約中、期限を過ぎると終了になる。停止した広告は期間にかかわらず停止中。終了時刻ちょうどの扱いは既存の配信判定に合わせる。

検索は広告名・本文・スポンサー名・リンク先に対応し、空白区切りの複数語はすべて一致する広告を表示する。「スポンサーのみ」は直接切り替え、「場所・並び順」から掲載場所と並び順を開く。掲載状況順、終了日時が近い順、掲載場所順、広告名順で並べられる。終了日時未指定は終了日時順の最後になる。上部の状態別件数は全広告の件数、一覧の件数は検索とフィルター適用後の件数を示す。

各カードには状態・スポンサー・掲載場所・期間を表示し、「編集・プレビュー・停止」を直接操作できる。削除と「複製して作成」は右上のメニューへまとめた。複製は元の広告を変更せず、リンク先・期間・スポンサー等を引き継いだ新規作成画面を開く。誤配信を防ぐため複製の初期設定は配信停止。必要な内容・掲載場所を直し、配信を有効にして保存する。削除には確認が必要。

編集画面は「広告の内容」「掲載場所とリンク先」「掲載設定」の3区分。広い画面はプレビューを横に表示し、スマホでは同じスクロール領域の先頭に置く。保存ボタンは下部に固定する。保存失敗時は入力内容を保持して再試行でき、保存中は二重操作を防ぐ。未保存の変更を閉じると破棄を確認する。不正な入力は対象欄へスクロールして案内する。

企業・店舗名、見出し、本文、画像URL、リンク先、表示場所、掲載期間、表示の重み、配信状態を設定する。掲載設定と同じ金色を使い、ライト／ダークモードのどちらでも文字のコントラストを確保する。

広告バナーは「詳しく見る」などの誘導文・矢印の行を省き、上下の余白も縮める。文字サイズは維持し、バナー全体のタップでリンク先を開く。管理画面のボタン文言入力は廃止したが、既存の ctaText データは保存時も保持する。

広告のプレビューは実際の広告カードと共通の表示部品を使う。プレビューではリンク遷移や広告の表示・クリック計測は行わない。既存の広告イベント in_app_ad_impression / in_app_ad_click は維持する。

日時・画像をクリアした場合も、保存先から古い値が消える。終了日時が開始日時以前の場合は保存しない。外部リンクは http / https に限定する。

## データと権限

bulletin_posts と in_app_ads に次のフィールドを追加した。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| isSponsored | bool | 金色のスポンサー枠 |
| sponsorName | string | 企業・店舗名。無効時は空文字 |

既存データにフィールドがなければ通常枠として扱う。データの一括移行は不要。

スポンサー情報の作成・変更はFirestoreルールで管理者に限定する。投稿者の本文編集は変更可能な項目のみ更新し、スポンサー情報や使用実績を上書きしない。広告の配信スイッチも配信状態のみ更新する。

本番利用にはアプリの配布と firestore.rules の反映が必要。この作業では本番ルールをデプロイせず、実際のスポンサー投稿や広告も登録していない。既存の未コミット変更を含むルール全体を、確認せずに一括デプロイしない。
