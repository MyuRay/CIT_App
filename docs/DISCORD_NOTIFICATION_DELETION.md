# Discord運営通知と退会時の削除

2026-11-15。ローカル実装・テスト済み。本番デプロイ・実データの送信や削除は未実施。

## 対象と仕組み

`functions/discord_notifications.js` が運営通知の送信と削除を担当する。新規登録、問い合わせ、新旧掲示板通知、クーポン、Cwitterの投稿・返信、ちばちゃんねる、通報を対象とする。個人に帰属しない共有の学食メニュー通知は対象外。

1. 関連ユーザーが存在し、無効化・削除処理中ではないことを確認する。
2. イベントIDから作った固定キーで送信を予約し、同じイベントの二重送信を防ぐ。
3. Discordには個人情報のない仮メッセージを `wait=true` で作る。
4. 取得したメッセージIDをFirestoreに保存し、削除要求・送信権限を再確認してから本文をPATCHする。
5. 退会処理は保存したIDでDiscord通知を削除してから、残りの非公開データ・Authアカウントの削除完了へ進む。

Discordへ送った直後にFirestore保存が失敗しても、追跡不能な個人情報入り通知が残らないようにする。仮メッセージだけが残る場合はある。返信には元投稿者、クーポン利用には投稿者と利用者、通報には通報者と対象者を関連付け、いずれかの退会でその通知全体を削除する。本文中に名前が書かれた第三者まで自動抽出・関連付けはしない。

`discord_notifications` にはUID、種別、Webhook ID、メッセージID、送信・排他状態等だけを記録する。本文、メール、Webhookトークンは保存しない。クライアントの読み書きは拒否する。メールの一部マスクは匿名化ではない。Discordで読む運用メンバーは内容から本人を識別できる場合がある。

## 障害時

- 送信中の排他期限は10分。削除が競合した場合、既存のアカウント削除ジョブが後から再試行する。
- Discordの429、401/403、通信エラー、解釈できない404は削除完了にしない。既存の15分ごとの退会再試行で再開する。
- Discordの明示的な「メッセージなし」「Webhookなし」だけは削除済みと扱う。
- 通知送信失敗は他の通知・アプリ処理を妨げないようサニタイズして記録する。送信失敗自体の定期再送は追加していない。同一イベントの再実行時には記録済みメッセージを利用する。
- Discord障害や削除用認証情報の不足により、退会処理の完了が遅れる場合がある。失敗ジョブを監視して復旧する。

## Webhookの変更

通常は種別ごとの既存Webhook設定を利用する。送信先Webhookを別のものへ変更する場合、過去の通知を削除するには元のWebhook URLも必要になる。削除用の旧URLを `DISCORD_WEBHOOK_URLS_FOR_DELETION` にJSON配列で設定できる。この値は認証情報なのでソース・ログ・Firestoreへ貼り付けない。現在は `https://discord.com/api/webhooks/...` およびAPIバージョン入りURLを扱う。

旧認証情報を削除する前に、該当Webhookの通知記録が残っていないことを確認する。認証情報の紛失・トークン変更時には復旧やDiscord側の削除手段を個別に検討する。記録だけ消して退会を完了扱いにしない。

## 反映の順序

1. 実際のWebhook設定と削除権限、海外サービスへの提供条件を確認する。
2. 本番との差分を確認し、`discord_notifications` のクライアント拒否ルールを反映する。ルール全体には他作業の差分があるため無確認で丸ごとデプロイしない。
3. 対象の送信トリガーと、削除ワーカー・再試行関数をセットで反映する。段階反映中に旧トリガーが送った通知は追跡対象外になる。
4. 専用のテストアカウント・非公開通知先で送信から退会削除まで検証し、導入日時を記録する。
5. `legal/README.md` の未解決事項を解消してから、公開ポリシー、ストア表示、アプリ内の文面・再同意を揃えて配信する。

導入前の通知に対応記録を後付けしてはいない。過去の通知の特定・削除と、継続保管が必要な記録の整理は別途実施する。

## 検証

`functions/test/discord_notifications.test.js` と `test/firestore/discord_notifications.test.cjs`。後者はFirestoreエミュレーターとHTTPモックを使い、保存前の個人情報送信防止、並行送信、退会との競合、削除再試行、複数所有者、旧Webhook、記録のアクセス拒否、Auth削除との順序を検証する。本物のDiscordへ送信・削除しない。

最終確認ではエミュレーター13件、単体2件が成功。通知先のスレッド設定を変更した後も、再送・削除では元のスレッド（スレッドなしを含む）を維持することも確認した。テストのFirestoreクライアントではメタデータサーバーの探索を無効にし、ローカル専用の認証値と `127.0.0.1:8089` を使用する。実際のクラウド認証情報は不要。

検証環境では当初のクラウドメタデータ探索が自動審査で拒否されたため、上記の設定で再実行した。テスト本体13件の成功後、エミュレーターバイナリの外部テレメトリー通信も自動審査で拒否された。外部通信は追加承認しておらず、本番の送信・削除を検証したものではない。
